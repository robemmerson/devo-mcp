# Detection library index

580 ready-made Devo SecOps detections (LINQ) from the Devo "Query and alert library", split by category.

## How to use

1. `grep -i` this file for a keyword, table, or MITRE id (e.g. `T1110`, `box.all.win`, `Spray`).
2. Open the category file named in column 2 and search for the detection name (`## <name>`); copy the ```linq block.
3. Queries are written as alert templates (`group every Xm ...` plus enrichment `select`s). For an investigation, narrow the time range and add filters; enrichment/`lu(...)` lines can be deleted if a lookup is missing.
4. Before running a detection, check its tables (column 3) against `devo.py tables --grep '<table>'` (the domain's cached live table list). If none of them has data, the query returns nothing or fails with "Unknown table"; union tables can also be empty when none of their sources are sent.

## Required lookups

Queries enrich results with `lu("<Lookup>", "<field>", key)` (or `` `lu/<Lookup>/<field>`(key) ``). The lookup must exist in the domain; **a query that references a missing lookup fails** -- remove those `select lu(...)` lines (they only add context columns) or create the lookup. Devo publishes example CSVs for the SecOps* lookups (uploaded with headers; first column is the key; do not rename headers): SecOpsAlertDescription, SecOpsAssetRole, SecOpsLocation, SecOpsAUTHAuthorizedAccess, SecOpsDomesticCountries, SecOpsEmbargoCountries, SecOpsFWAuthorizedAccess, SecOpsGWL, SecOpsIANAPortAssignment, SecOpsWinPermittedDomains, SecOpsWinPermittedLocalAccounts.

## Parent-name tables

Some detections query a parent name such as `cloud.aws.cloudtrail`, `cloud.office365` or `cloud.azure`, which reads every table under it (slow, like a union). If `devo.py tables` lists only subtables, retarget the query to the specific subtable for the service (e.g. `cloud.aws.cloudtrail.iam`).
