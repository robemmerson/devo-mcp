### What every `management.*` row looks like

- **One row = one audit record** of the Management Activity API. Common fields: `Id` (record GUID: the
  dedupe key), `Operation`, `RecordType` (int), `Workload`, `UserId`, `UserKey`, `UserType` (int),
  `OrganizationId` (constant tenant GUID), `ClientIP`, `ResultStatus` (not in every table), and
  **`message`: the full original JSON record** (`rawMessage` in `powerplatform`). `hostname` is the Devo
  collector, not an entity.
- **The schema is a wide generic union** shared by most of these tables (Exchange-, DLP-, Power BI-
  and Yammer-style columns appear in the Teams schema). Only a fraction is ever filled per table, so read
  `devo.py fields <table>` rather than `schema`. **Many record fields are not columns at all and exist
  only inside `message`**: `CreationTime` (all tables); Teams `ChatThreadId`, `MessageId`,
  `CommunicationType`, `ChatName`, `Members`, `Attendees`, `MeetingDetailId`, `CallId`, `JoinTime`,
  `LeaveTime`, `AppAccessContext`, `DeviceId`, `ParticipantInfo`, `MessageFiles`, `MessageURLs`;
  SharePoint/OneDrive `SharingLinkScope`, `Permission`, `EventData`, `GeoLocation`, `IsManagedDevice`,
  `DeviceDisplayName`, `AuthenticationType`, `Platform`, `AppAccessContext`, `ZipFileName`; Exchange
  `Folders`/`FolderItems` (MailItemsAccessed), `Item.Recipients`, `OperationCount`, `ClientRequestId`.
- **Reading `message`**:
  - string value: `str(jsonparse(message)["ChatThreadId"])`
  - **number value: `int(jsonparse(message)["OperationCount"])`. `str()` on a JSON number returns an
    empty string**, so `int(str(...))` silently gives null and filters/sums return 0 rows.
  - nested / array element: `str(jqeval(jqcompile(".Attendees[0].UPN"), jsonparse(message)))`,
    `jqeval(jqcompile(".AppAccessContext.AADSessionId"), jsonparse(message))`. jq `select(...)` is
    rejected (`Invalid filter … in operation jqcompile`); a missing key comes back as the string `None`.
  - whole array as text: `stringify(jsonparse(message)["MessageFiles"])`.
  - fast pre-filter for an id anywhere in the record: `message -> "<id>"` (case-sensitive; one id is
    fast even over weeks, many OR'd ids get slow). Then extract the field to make the match exact.
  - Flattened `*_str` columns (e.g. `CopilotEventData__AccessedResources_Name_str`,
    `Members_UPN_str`, `Parameters_Name_str`) are **comma-joined lists**: fine for `->`/`weakhas`, but
    values containing commas break the alignment between sibling `_str` columns. Parse the JSON column
    (or `message`) in Python for anything per-element.

### Time: `eventdate` is ingestion time, not event time

**Lag is variable and batch-driven: run `devo.py lag --tables office365` before relying on a recent
window.** It measures `eventdate − CreationTime` per hour of ingestion, now, and prints p50/p95, the
worst hour, the latest hour and the newest event per table. Don't assume a fixed figure: a workload
that was days behind can catch up in one back-fill, and one that was near real time can fall behind,
so "it's a week behind, so yesterday can't be there yet" can be wrong in either direction.

- Typical behaviour: Teams, Copilot and the small workloads are usually minutes behind; SharePoint,
  OneDrive and Exchange can arrive in bulk back-fills, sometimes days late; Power BI often shows a
  steady lag of tens of minutes.
- **Collection outages**: after an outage, records created during it can arrive days late or never.
  `group every 1d` on `eventdate` hides this; group by creation day instead (recipe below).
- **Holes**: back-fills can leave whole created-hours missing. When a table is behind, for "what did X
  do in SharePoint yesterday" the honest answer can be "not collected yet": run `lag` and the coverage
  recipe below, and say so.
- **Query recipe for these tables**: search a wider `eventdate` window than the period you want (the
  `lag` p95 tells you how much wider) and filter or group on `CreationTime` from `message`. Report times
  from `CreationTime` (UTC, no `Z`, second precision) or, better, the event's own times
  (`JoinTime`/`LeaveTime`, `StartTime`/`EndTime`).
- Teams meeting records (`MeetingDetail`, `MeetingParticipantDetail`, `CallParticipantDetail`) are
  **created hours after the meeting ends**, so use `JoinTime`/`LeaveTime`/`StartTime`/`EndTime`, not
  `CreationTime`/`eventdate`.
- A back-fill can land thousands of rows in the same minute, so a raw-row query over that window hits
  `--limit` in one chunk while the others are far below it. `--auto-split` (on by default for raw-row
  queries with `--limit` ≥ 1000) halves full windows and re-runs them, but no time split separates rows
  ingested in the same minute: when it still warns, raise `--limit`.

### Duplicates

Duplicates come from **overlapping back-fill batches**, so the ratio depends on how the data arrived:
SharePoint and OneDrive can hold the same record several times over after repeated back-fills, and
none at all when data arrived normally. Other workloads have few or none (some around outages).
**Always count SharePoint/OneDrive with `hllppcount(Id)`, not `count()`**, and drop repeated `Id`s when
parsing rows (`devo.py timeline` does).

### Entity fields

**`UserId` forms** (mixed case: match with `weakhas`/`eqic`, never `=`):

| Form | Where |
|---|---|
| UPN (often mixed case; a tenant can have several UPN domains) | all user activity |
| `#ext#` guest UPN `name_<domain>#ext#@<tenant>.onmicrosoft.com`, and `urn:spo:guest#<email>` | SharePoint/OneDrive guests (`urn:spo:guest` when signed in with an email OTP) |
| `anonymous`, `urn:spo:tenantanon#…`, `urn:spo:anon#…` | SharePoint/OneDrive "Anyone" links (`AnonymousLinkUsed`, `SharingLinkUsed`) |
| `app@sharepoint` (identify the app with `ApplicationDisplayName`/`ApplicationId`) | SharePoint/OneDrive app-only access: typically most bulk `FileDownloaded` rows |
| `SHAREPOINT\system`, display names such as `Purview Data Lifecycle Management service`, `AAD to SharePoint Sync` | retention (`FileRecycled`, `FileDeletedFirstStageRecycleBin`, `FilePreserved`, `FileVersionDeleted`): exclude from "user deleted files" |
| App display names (`Microsoft Teams Sync`, `Microsoft Teams Graph Service`, a backup app's name, `Application`), `UserType = 5` | Teams `MemberRemoved`, `MessagesExported`, app clean-up |
| `.cid.<16 hex>` | Teams personal-account (consumer) users in chats with tenant users |
| phone number `+<digits>`, 32-hex id | Teams PSTN / bot call participants |
| object GUID | MS To Do (the Entra object id, matching Teams `UserKey`; `UserKey` is a PUID), Planner (some rows, app reads with `UserType = 5`), Power BI (`UserType = 6`), M365 `azureactivedirectory` |
| `Not Available` (with `UserType = 4`) | many M365 `azureactivedirectory` `UserLoggedIn` rows (`SAS:BeginAuth`/`SAS:EndAuth` MFA steps): the user is only in `UserKey`/`Actor`/`ObjectId` (object GUID) |
| `ServicePrincipal_<guid>` | M365 `azureactivedirectory` directory changes by apps |
| `NT SERVICE\…`, SID `S-1-5-…` | Exchange admin cmdlets / system mailbox access |
| `ThreatIntel`, `SecurityComplianceAlerts`, `SecurityComplianceInsights`, `UploadDefaultPhotoComplianceAssistant` | system writers in threatintelligence / securitycompliancecenter / microsoft365group |

`UserKey` is the actor's **Entra object id** in Teams (also the suffix of `UserMRI` `8:orgid:<oid>`),
Copilot and Planner; in SharePoint/OneDrive it is a claim string (`i:0h.f|membership|<upn>` for users,
`i:0i.t|<app-guid>|…` for `app@sharepoint`, `AgenticApp_i:0h.f|…` for agents); in Exchange a 16-hex PUID.
`UserType` (Microsoft's enum): 0 regular user, 2 admin, 4 system, 5 application, 6 service principal;
7 and 15 appear on SharePoint/OneDrive retention and guest rows.

**`ClientIP` forms** (by table):

| Form | Where |
|---|---|
| plain IPv4 / IPv6 | everywhere |
| `::ffff:a.b.c.d` (IPv4-mapped) | Teams `MessageSent`, `MemberAdded`, `TabAdded`; Microsoft Forms |
| **last octet masked `a.b.c.x`**, and **private RFC1918 addresses** | Teams `CallParticipantDetail` / `MeetingParticipantDetail` / `MeetingDetail` (the client's local address, mostly private): useless for geo/attribution |
| `a.b.c.d:port`, `[ipv6]:port` | Exchange admin cmdlets (`RecordType 1`, e.g. `New-InboxRule`, `Set-Mailbox`) |
| comma list `a.b.c.d, e.f.g.h` | securitycompliancecenter |
| two letters `NA` | MS To Do (not an IP) |
| blank | Exchange `ClientIP` on mailbox-item records (use **`ClientIPAddress`**, always filled), Planner/Power BI app rows, `microsoft365group`, `mip`, `projectfortheweb` (no IP at all) |

`Client` duplicates `ClientIP` in most tables. `ActorIpAddress` duplicates it in `azureactivedirectory`.
For an IP pivot use `ClientIP -> "203.0.113.10"` (catches the `::ffff:`/`:port` forms).

### `cloud.office365.management.microsoftteams`

One row = one Teams action by one actor. Teams audit **never contains message text** (not in any field or
in `message`); you get who/when/which conversation/message id, links, file URLs, reactions, members and
meeting attendance.

**Operations**, by purpose:
- Messages and chats: ChatCreated · ChatRetrieved · MessageCreatedHasLink · MessageCreatedNotification ·
  MessageDeleted · MessageEditedHasLink · MessageEditedHasViolation · MessageRead ·
  MessageReadReceiptReceived · MessageSent · MessageUpdated · MessageUpdatedNotification ·
  MessagesExported · MessagesListed · ReactedToMessage.
- Meetings, calls and sessions: CallParticipantDetail · MeetingDetail · MeetingParticipantDetail ·
  TeamsSessionStarted · TeamsUserSignedOut.
- Teams, channels and members: ChannelAdded · ChannelDeleted · ChannelSettingChanged · MemberAdded ·
  MemberRemoved · TeamCreated · TeamDeleted · TeamSettingChanged · UserAccepted.
- Apps, bots, tabs and connectors: AppCleanedUpAfterExpiration · AppDeleted · AppInstalled ·
  AppUninstalled · AppUpgraded · BotAddedToTeam · ConnectorAdded · PerformedCardAction · TabAdded ·
  TabUpdated · ViewedApprovalRequest.
- Admin and settings: TeamsAdminAction · WriteUserObjPreference.

- `MessagesListed` / `MessagesExported` / `MessageCreatedNotification` / `ChatRetrieved` are **Graph API
  reads by apps** (backup/compliance tools; `UserType 5`, `UserId` = app display name, `TargetUserId` =
  whose messages). `MessagesExported` lists exported messages in `Messages[]` (`ChatThreadId`, `Id`,
  `SizeInBytes`): a `message -> "<thread>"` search hits them, so filter on the top-level `ChatThreadId`.
- `MessageCreatedHasLink` / `MessageEditedHasLink` are **user messages containing a URL or file**; most
  1:1 and group-chat sends appear only as these, while `MessageSent` is mostly channel and meeting-chat
  posts. Few (thread, `MessageId`) pairs have both. Treat MessageSent + MessageCreatedHasLink as "sent"
  and dedupe on `MessageId`.
- **Links and URLs**: `MessageURLs` is on every `MessageCreatedHasLink` and `MessageEditedHasLink` row,
  rarely on `MessageSent` rows, and never on `MessageUpdated`. It mixes real links, file URLs and
  Teams-internal URLs (inline images, emoji on `*.teams.microsoft.com`, `*.skype.com`);
  `MessageLinks[].Url` (on some HasLink rows) holds the hyperlinks and `MessageFiles[].FileUrl` the
  files. So a person's links are in their HasLink rows only: an empty `MessageURLs` search over their
  `MessageSent` rows doesn't mean they shared no links. `devo.py teams` separates files from links and
  drops the Teams-internal URLs.

**Id fields by conversation type:**

| Conversation | Thread id | Other ids | Name |
|---|---|---|---|
| 1:1 chat (`CommunicationType = OneOnOne`) | `ChatThreadId` = `19:<oidA>_<oidB>@unq.gbl.spaces` (**both participants' object ids**; the actor's `UserKey` is one of the pair) or `19:uni01_<base32>@thread.v2` | `MessageId` | `ItemName` = the thread id; no `ChatName` |
| Group chat (`GroupChat`) | `19:<32 hex>@thread.v2` | `MessageId` | `ChatName` / `ItemName` (empty for unnamed chats) |
| Meeting chat (`Meeting`) | `19:meeting_<base64>@thread.v2` (same string, URL-encoded, inside `MeetingDetail.MeetingURL`) | `MeetingDetailId`, `ICalUid`, `CallId` | `ItemName` = `ScheduledMeeting`/`RecurringMeeting`/`AdHocMeeting…` on meeting records |
| Channel (`Channel`) | **`ChannelGuid`** column `19:<hex>@thread.tacv2` (no `ChatThreadId`) | `TeamGuid` (`19:…@thread.tacv2`), `AADGroupId` (the M365 group GUID, message-only), `MessageId`, `ParentMessageId` (= root post of a reply thread) | `ChannelName`, `TeamName` (columns) |
| Team membership (`Team`) | `TeamGuid` | `AADGroupId` | `TeamName` |
| 1:1 / group call | `CallId` (GUID) | | `ItemName` e.g. `Missed` |

Per operation (message-only unless noted): messages (`MessageSent`, `MessageCreatedHasLink`,
`MessageUpdated`, `MessageEditedHasLink`, `ReactedToMessage`, `MessageRead`) carry `ChatThreadId`
(not on channel posts), `MessageId` (epoch-ms-like integer string; `MessageVersion` changes on edit),
`CommunicationType`, `ChatName`, `DisplayName` (actor's display name), `ParticipantInfo`
(`HasGuestUsers`, `HasForeignTenantUsers`, `ParticipatingDomains`), `MessageURLs`/`MessageLinks`,
`MessageFiles[].FileUrl` (URL-encoded SharePoint/OneDrive URL), `MessageImages`, `MessageReactionType`
(`like`, `heart`, …), `IsCopilotMentioned`, `DeviceId`, `ExtraProperties` (`TimeZone`). `MemberAdded` /
`MemberRemoved` / `ChatCreated` carry `Members[]` (`UPN`, `DisplayName`, `Role`) and the
**`Members_UPN_str`, `Members_DisplayName_str`, `Members_Role_str` columns are filled**.
`MeetingDetail`: `StartTime`, `EndTime`, `Organizer.UserObjectId`, `CommunicationSubType`
(ScheduledMeeting/RecurringMeeting/AdHocMeeting), `Modalities` (Audio, Video, ScreenSharing),
`MeetingURL`, `ICalUid`, `ArtifactsShared`. **`MeetingParticipantDetail`: one row per participant join;
the participant is `Attendees[0]` (`UPN`, `DisplayName`, `UserObjectId`, `Role`, `RecipientType`,
`IsAADGuest`; external/anonymous joiners have only `DisplayName`, typically with `Role` 3; the
organizer object carries `Role` 2), with `JoinTime`, `LeaveTime`, `DeviceInformation`; `UserId` is the
meeting organizer, not the participant** (constant per meeting and equal to the `MeetingDetail`
`UserId`). `CallParticipantDetail` is the same for calls (`CallId`). `TeamsSessionStarted` (sign-in to
the client: `DeviceId`, public `ClientIP`; `ObjectId` `Unknown (Unknown)`).

**What is available for a conversation**: participants (senders, reactors, editors; `Members` changes;
meeting attendees with join/leave times), message ids and times, edits (new `MessageVersion`), reply
structure in channels (`ParentMessageId`), links and file URLs shared, reactions, meeting start/end,
modalities and organizer, device and client IP per actor. **Not available**: message text or subjects,
the recipients of an individual 1:1/group message (only the thread), and reads (MessageRead is rare).
Use Copilot (`TeamsMeeting` contexts) and SharePoint (`TeamsMeetingRecordingUploaded`,
`FileTranscriptContentAccessed`) for meeting artefacts.

### `cloud.office365.management.sharepoint` and `.onedrive`

Same shape; OneDrive = personal sites (`https://<tenant>-my.sharepoint.com/personal/<user>/…`), SharePoint =
team/communication sites (`/sites/<site>/…`). One row = one file/list/page/sharing/site action.
**Can arrive in back-filled batches, with holes and duplicates** (see above; run `devo.py lag`).

- **File identity**: `ObjectId` = full decoded URL of the item (e.g.
  `https://<tenant>.sharepoint.com/sites/<site>/Shared Documents/<path>/<file>.xlsx`); `SiteUrl`
  (site root, trailing `/`); `SourceRelativeUrl` (folder path within the site); `SourceFileName`,
  `SourceFileExtension`; `ListItemUniqueId` (**GUID of the item, stable across renames per Microsoft; the Copilot join
  key**); `ListId`, `WebId` (site GUID), `Site` (message-only GUID); `ItemType` File / Folder
  / List / Page / Site / Web. Renames/moves/copies: `DestinationFileName`, `DestinationRelativeUrl`.
- **Who/where**: `UserId`, `ClientIP`, `UserAgent`, `ApplicationDisplayName` / `ApplicationId` (client
  app: OneDrive sync, browser, Teams, …), `BrowserName`, `MachineId` / `MachineDomainInfo` (sync
  client), message-only `DeviceDisplayName`, `Platform` (WinDesktop, Wac, MacOS, iPhone, …),
  `IsManagedDevice`, `AuthenticationType` (OAuth, FormsCookieAuth), `GeoLocation` (data location
  code, e.g. `NAM`, `EUR`), `CorrelationId`.
- **File trail operations**: view FileAccessed / FileAccessedExtended /
  FilePreviewed / PageViewed; download FileDownloaded / FileSyncDownloadedFull (sync client); edit
  FileModified / FileModifiedExtended / FileUploaded / FileSyncUploadedFull / FileUploadedPartial /
  FileRenamed / FileMoved / FileCopied / FileCheckedIn/Out; delete FileRecycled /
  FileDeletedFirstStageRecycleBin / FileDeletedSecondStageRecycleBin / FileDeleted / FileVersionDeleted
  / FolderRecycled; restore FileRestored; other ListItemUpdated, SearchQueryPerformed,
  `FileTranscriptContentAccessed`, `TeamsMeetingRecordingUploaded`, `DLPRuleMatch`. `FileDownloaded`
  with message-only `ZipFileName` (+ `UserSessionId`) = a multi-file "Download as zip".
- **Sharing**: SharingSet (permission granted; `TargetUserOrGroupName`/`TargetUserOrGroupType` =
  Member / Guest / SharePointGroup / SecurityGroup), SharingInvitationCreated (invite to an external
  address), SharingLinkCreated / SharingLinkUpdated (message `SharingLinkScope` = `SpecificPeople` /
  `Organization` / `Anyone`, `Permission` = View / Edit / Review / RestrictedView), AnonymousLinkCreated,
  CompanyLinkCreated, SecureLinkCreated, AddedToSecureLink / AddedToSharingLink (recipient in
  `TargetUserOrGroupName`), SharingRevoked, SharingInheritanceBroken, AccessRequestCreated/Approved; and
  link **use**: AnonymousLinkUsed / SharingLinkUsed with `UserId = anonymous` (Anyone links),
  SecureLinkUsed, CompanyLinkUsed. `UniqueSharingId` is filled on link creation/use rows (not verified
  as a join). `SharingLinkScope` reads `Uninitialized` on the SecureLink/Company/Anonymous/SharingSet
  variants; the operation name carries the scope there. `EventData` is a small XML-ish string
  (`<PermissionsGranted>`, `<Type>`, …).
- **Guests/external**: `UserId -> "#ext#"`, `urn:spo:guest#…` (email one-time-passcode guests; their
  `EmailAuthOTPAuthenticationSucceeded` rows appear alongside their file access), `anonymous`; recipients `TargetUserOrGroupType = "Guest"`.
- `app@sharepoint` usually accounts for most bulk downloads (backup, migration and indexing apps can
  read very large numbers of files per hour); retention services do the bulk deletions. Always split
  human UPNs from these.
- Other SharePoint-only operations: `BaselineSecurityModeThirdPartyAppHPA`, `PreAuthTokenUsed(Extended)`,
  `SignInEvent`, `ClientViewSignaled`, `SiteCollectionAdminAdded/Removed`, `SiteCollectionCreated`,
  `SiteDeleted`, `SharingPolicyChanged`, `GroupAdded`/`AddedToGroup`.

### `cloud.office365.management.exchange`

Mailbox audit (`RecordType` 2 item, 3 bulk item, 50 MailItemsAccessed/AttachmentAccess) and admin
cmdlets (`RecordType` 1). Lag is batch-driven: check with `devo.py lag`. No subject-free privacy here:
**`Item_Subject`, `AffectedItems_Subject_str`, `Folders[].FolderItems[].Subject` and recipients are
logged**. Mailbox operations: access (AttachmentAccess, FolderBind, MailItemsAccessed), change
(Create, Update, Move, MoveToDeletedItems, SoftDelete, HardDelete), sending (Send, SendAs,
SendOnBehalf). Admin cmdlets include mailbox and group settings (`New-Mailbox`, `Set-Mailbox`,
`Remove-StoreMailbox`, `Set-MailboxAutoReplyConfiguration`, `Set-MailboxCalendarConfiguration`,
`New-UnifiedGroup`, `Set-UnifiedGroup`), permissions (`AddFolderPermissions`,
`ModifyFolderPermissions`), inbox rules (`New-InboxRule`, `Enable-InboxRule`) and policy
(`Set-ConditionalAccessPolicy`), …

- Actor vs mailbox: `UserId` (actor UPN; SID or `NT SERVICE\…` for system), **`MailboxOwnerUPN`**,
  `MailboxGuid`, `MailboxOwnerSid`, `LogonUserSid`, **`LogonType` 0 owner / 1 admin / 2 delegate**,
  `ExternalAccess` (True for Microsoft-side admin access), `CrossMailboxOperation`, `SendAsUserSmtp` /
  `SendOnBehalfOfUserSmtp`.
- Client: **`ClientIPAddress`** (always filled; `ClientIP` only on some rows and with `:port` on cmdlets),
  `ClientInfoString` / `ClientInfoString_client` (`Client=OWA`, `Client=MSExchangeRPC` (Outlook desktop),
  `Client=REST;Client=RESTSystem` (Graph/REST apps, typically the bulk of MailItemsAccessed and
  AttachmentAccess), `Client=OutlookService`), `ClientProcessName` (`OUTLOOK.EXE`),
  `ClientAppId`/`AppId`, `UserAgent`, `SessionId`, `AppAccessContext__AADSessionId`,
  `AppAccessContext__UniqueTokenId`, `TokenObjectId`.
- Item: `Item_Id`, `Item_ImmutableId`, `Item_InternetMessageId` (`<…@…>`), `Item_Subject`,
  `Item_Attachments` (`name (bytes); …`), `Item_SizeInBytes`, `Item_ParentFolder_Path` (`\Inbox`,
  `\Sent Items`, `\Drafts`, `\Outbox`, `\Calendar`), `DestFolder_Path` (moves), `AffectedItems*` (deletes,
  moves). Recipients of Send/SendAs only in `message` `Item.Recipients[]` (`Address`, `Name`).
  MailItemsAccessed items are message-only `Folders[].FolderItems[]` with `OperationCount` (number) and
  `OperationProperties` `MailAccessType` = Bind / Sync.
- Admin cmdlets: `ObjectId` (target), **`Parameters_Raw`** (full JSON `[{"Name","Value"}]`, e.g. the inbox
  rule's `From`, `SentTo`, `MoveToFolder`, `ForwardTo`, `DeleteMessage`), `Parameters_Name_str`.

### `cloud.office365.management.copilot`

One row = one Copilot exchange (prompt + responses); usually near real time. Operations:
CopilotInteraction (nearly all), LiveNotesUpdate, TeamCopilotMsgInteraction. **No prompt or response
text.**
- `UserId` (UPN), `UserKey` (object id), `ClientIP` (public), `AppIdentity`
  (`Copilot.M365Copilot.WebChat`, `.Bizchat`, `.Apps`, `Copilot.Studio.Declarative.T_<id>` (custom
  agents), `MicrosoftAgent.<name>`, `Copilot.TeamCopilot.LiveNotes`), `CopilotEventData__AppHost`
  (Office, Outlook, OutlookSidepane, Teams, Word, Excel, Edge, …), `AgentName`/`AgentId`,
  `CopilotEventData__ConversationId` (GUID; one per Copilot conversation), `CopilotEventData__ThreadId`
  (`19:…@thread.v2`), `CopilotEventData__LicenseType`, `…ModelTransparencyDetails_ModelName_str`.
- **`CopilotEventData__AccessedResources`** (JSON array string): what the answer used. Element `Type`:
  `CITATION` / no type (web pages, `SiteUrl` = URL), `WebSearchQuery`, `http://schema.skype.com/HyperLink`,
  file types (`docx`, `xlsx`, `pptx`, `pdf`, … with `Name`, `Id` `SPO_<base64>`, `SiteUrl` (file or
  `Doc.aspx` link), **`listItemUniqueId`**), `EmailMessage` (`Id` = InternetMessageId, `SiteUrl` = OWA
  link), `People`, `TeamsMeeting`; `Action` Read (or write); `PolicyDetails` (sensitivity/IRM/CA
  outcome), `XPIADetected` (prompt-injection flag).
- `CopilotEventData__Contexts`: what Copilot was invoked on (a file URL with `Type` docx/xlsx/…,
  `TeamsMeeting`/`TeamsChat` with the Teams thread id, local `C:\Users\…` paths for uploads).
  `CopilotEventData__Messages`: ids with `isPrompt` and `JailbreakDetected` only.

### `cloud.office365.management.azureactivedirectory` (M365 copy of Entra events)

The legacy Office audit view of Entra: `UserLoggedIn` / `UserLoginFailed` and directory changes named
in sentences (`Add member to group.`, `Update user.`, `Change user password.`, `Add member to role.`,
`Consent to application.`, `Add service principal credentials.`, …). Fields: `UserId`, `ObjectId`
(target), `ResultStatus` Success/Failed, `LogonError` (`UserDisable`, `DeviceNotCompliant`, …),

`ApplicationId`, `Actor_ID_str` / `Target_ID_str` (comma lists of ids incl. UPN and PUID),
`ExtendedProperties_Name_str`/`_Value_str` (`ResultStatusDetail`, `UserAgent`, `RequestType` e.g.

`DeviceProperties_Values` arrays (device `DisplayName` = hostname, `OS`, `BrowserType`, `IsCompliant`,
`IsCompliantAndManaged`)**. Prefer the Entra tables (`cloud.azure.ad.*signin`, `.audit`) for sign-ins
(error codes, CA, MFA detail, session ids); use this one for the device hostname of a browser sign-in and

### Speed

Management tables usually answer in seconds for days to weeks of `group by` or exact-id filters, and
chunking is generally not needed. The slow cases: a multi-week `group by Id` on SharePoint/OneDrive,
and many OR'd `message -> "…"` terms.

### Linking recipes

**Coverage first.** What creation days does SharePoint (or Exchange, OneDrive) actually hold, and when
were they ingested? Missing or tiny days are collection holes, not quiet days.
```linq
from cloud.office365.management.sharepoint
select substring(str(jsonparse(message)["CreationTime"]), 0, 10) as created_day
group by created_day
select count() as n, min(eventdate) as first_ingested, max(eventdate) as last_ingested
```

Ingestion lag per day (any table):
```linq
from cloud.office365.management.microsoftteams
select parsedate(str(jsonparse(message)["CreationTime"]), "YYYY-MM-DD[T]HH:mm:ss", "UTC") as created,
  (epoch(eventdate) - epoch(created)) / 60000 as lag_min
group every 1d
select count() as n, min(lag_min) as min_lag, avg(lag_min) as avg_lag, max(lag_min) as max_lag
```

Filter on real event time (one created-hour, searched across a wider ingestion window):
```linq
from cloud.office365.management.sharepoint
select parsedate(str(jsonparse(message)["CreationTime"]), "YYYY-MM-DD[T]HH:mm:ss", "UTC") as created
where created >= parsedate("<YYYY-MM-DD>T17:00:00", "YYYY-MM-DD[T]HH:mm:ss", "UTC"),
  created < parsedate("<YYYY-MM-DD>T18:00:00", "YYYY-MM-DD[T]HH:mm:ss", "UTC")
group by Operation
select count() as n
```

#### Teams: person → conversations

**`devo.py teams <upn> --from … --to … --tz <IANA zone> --out teams.json` does all of this section in
one command**: it resolves the UPN to the object id, finds the conversations the person is in (their
own actions, 1:1 thread ids containing their object id, chats they were added to, meetings they
attended or organised), pulls those threads whole, and writes conversations (type, other parties as
UPNs, sent / edits / reactions / files / links for the person and for the others), meetings per
occurrence (`MeetingDetailId`: start/end, organizer, modalities, artifacts; per participant join and
leave times, device and what they shared, e.g. `screenShared`), calls (`CallId`), every file and link
shared, and daily counts. Times are `CreationTime`/`JoinTime`/`StartTime`, never `eventdate`. Channel
threads count only the person's own posts (team channels are busy: counting everyone's posts would
inflate the person's activity many times over). `devo.py teams 19:<thread>` does the same for one
conversation. The recipes below are the building blocks, for variants.

Every thread and channel the person acted in:
```linq
from cloud.office365.management.microsoftteams
where weakhas(UserId, "jsmith")
select str(jsonparse(message)["ChatThreadId"]) as chat_id,
  str(jsonparse(message)["CommunicationType"]) as comm_type
group by UserId, comm_type, chat_id, ChannelGuid, ItemName
select count() as events, min(eventdate) as first_seen, max(eventdate) as last_seen
```

1:1 chats the person is in **even if they never acted** (their object id is in the thread id; get it
from `UserKey` of any of their rows). Also shows the other party's actions:

For a readable timeline, pull raw records and parse them (one line per event, deduped by `Id`):
```sh
devo.py query 'from cloud.office365.management.microsoftteams where message -> "19:meeting_<id>@thread.v2" select eventdate, Operation, UserId, ClientIP, message' --from 3d --limit 0 --format jsonl --out conv.jsonl
```
```python
import json, sys, urllib.parse
seen, events = set(), []
for r in map(json.loads, open("conv.jsonl")):
    m = json.loads(r["message"])
    if m["Id"] in seen:
        continue
    seen.add(m["Id"])
    op, who = m["Operation"], m.get("UserId")
    if op == "MeetingParticipantDetail":
        a = m["Attendees"][0]
        events.append((m["JoinTime"], "joined", a.get("UPN") or a.get("DisplayName"), f'left {m["LeaveTime"]} role={a.get("Role")}'))
    elif op == "MeetingDetail":
        events.append((m["StartTime"], "meeting", who, f'{m.get("CommunicationSubType")} {m["StartTime"]}..{m["EndTime"]} {m.get("Modalities")}'))
    elif op in ("MemberAdded", "MemberRemoved", "ChatCreated"):
        events.append((m["CreationTime"], op, who, ",".join(x.get("UPN", "") for x in m.get("Members", []))))
    else:   # messages, reactions, edits; MessagesExported rows are app backups (UserId = app name)
        files = [urllib.parse.unquote(f["FileUrl"]) for f in m.get("MessageFiles", [])]
        events.append((m["CreationTime"], op, who, f'msg={m.get("MessageId")} parent={m.get("ParentMessageId", "")} files={files}'))
for e in sorted(events):
    print(*e, sep=" | ")
```

#### External sharing and guest creation

Sharing a file with an outside address does two things: SharePoint/OneDrive log the share, and (when
the tenant uses Entra B2B for SharePoint) Entra creates or invites a guest account. Put both sides
on one timeline.

1. **The share** (run on `onedrive` too). `SharingInvitationCreated` = an invitation to an address
   that has no account yet; `SharingSet` = permission granted to an existing user/guest/group;
   `AddedToSecureLink` = a recipient added to a specific-people link; `AnonymousLinkCreated` = an
   Anyone link (no recipient). The recipient is `TargetUserOrGroupName`, its kind
   `TargetUserOrGroupType` (`Guest` for outsiders):
   ```linq
   from cloud.office365.management.sharepoint
   where Operation in {"SharingInvitationCreated", "SharingSet", "AddedToSecureLink", "AnonymousLinkCreated"},
     TargetUserOrGroupType = "Guest" or Operation in {"SharingInvitationCreated", "AnonymousLinkCreated"}
   select parsedate(str(jsonparse(message)["CreationTime"]), "YYYY-MM-DD[T]HH:mm:ss", "UTC") as created
   group by UserId, Operation, TargetUserOrGroupName, TargetUserOrGroupType, SiteUrl, ObjectId
   select count() as n, min(created) as first, max(created) as last
   ```
2. **The guest account** in the Entra audit log: `Invite external user` (service `Invited Users`),
   `Add user` with a `#EXT#` UPN (the guest object being created), `Redeem external user invite`
   (service `B2B Auth`: the guest accepted) and `Delete external user`. Count on one copy
   (entra-graph.md, audit duplicates). The guest's UPN is in `targetResources`
   (`jsmith_example.com#EXT#@<tenant>.onmicrosoft.com`); `jqeval` returns JSON, so wrap it in `str()`
   before matching:
   ```linq
   from cloud.azure.ad.audit
   where operationName in {"Invite external user", "Add user", "Redeem external user invite", "Delete external user"},
     isnotnull(tenantId), tenantId != "-"
   select str(jqeval(jqcompile(".[0].userPrincipalName"), properties_targetResources)) as target
   where target -> "#EXT#"
   group by operationName, properties_result, target, properties_initiatedBy_user_userPrincipalName, properties_initiatedBy_app_displayName
   select count() as n, min(eventdate) as first, max(eventdate) as last
   ```
3. **Join in time.** Match the recipient address from step 1 to the guest UPN from step 2 (the
   `#EXT#` form replaces `@` with `_`) and the sharer `UserId` to the inviter. A share followed
   within minutes by `Invite external user` / `Add user` for the same address is one action. An
   invite can be initiated by a Microsoft app on the user's behalf rather than by the user, so
   check both initiator fields. A guest created with no matching share was invited some other way
   (admin portal, Teams, an access package): find the initiator.
4. **Then what the guest did** ("What guests and anonymous users did" above) and their sign-ins
   (guest rows in `cloud.azure.ad.signin` carry the `#EXT#` UPN or the home-tenant UPN; check both).

#### SharePoint / OneDrive: download bursts as staging evidence

When hunting data exfiltration, a burst of downloads by one person just before an external upload

Then one person's downloads as rows, bucketed and de-duplicated on `Id` in Python; run it on
`onedrive` too:
```linq
from cloud.office365.management.sharepoint
where Operation = "FileDownloaded", weakhas(UserId, "jsmith")
select str(jsonparse(message)["CreationTime"]) as created,
  str(jsonparse(message)["ZipFileName"]) as zip_name
select Id, SourceFileName, SourceRelativeUrl, SiteUrl
```
Gotchas:
- De-duplicate on `Id`: back-fills repeat records (see Duplicates).
- Don't use `--chunk` with the bucket query: chunks split by `eventdate` and would cut a creation-time
  bucket in two. These tables usually answer in seconds unchunked.
- In a back-fill, one chunk of raw rows can exceed `--limit` (thousands of rows can share a minute):
  keep `--auto-split` on and raise `--limit` if it still warns.
- `ZipFileName` is set when several files were downloaded as one zip. On the endpoint such a download
  typically lands as `OneDrive_<n>_<date>.zip` (see `../cross-tool-sentinelone.md`).

**Hash encodings differ between tables.** `AtpDetection` `FileData_SHA256` is base64 (44
characters ending in `=`), while the SharePoint/OneDrive record's `SHA256Hash` (a key inside
the `message` JSON, not a column: `jsonparse(message)["SHA256Hash"]`, or search `message`) and
EDR/Sysmon hashes are hex. Convert before joining or searching other tables:
```python
import base64; base64.b64decode("<base64>").hex()                  # base64 -> hex
import base64; base64.b64encode(bytes.fromhex("<hex>")).decode()   # hex -> base64
```
Hex case varies by source, so compare case-insensitively (`weakhas`, `lower()`). Look for the file as
`FileMalwareDetected` in **both** `.sharepoint` and `.onedrive`: a detection rule on one of them
misses the other (investigations.md §4).
